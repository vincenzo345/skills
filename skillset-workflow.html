The shared path

A task does not need every skill. The stages show where to look for help; the route cards below show common combinations.

01 · ROUTE

Identify the work

Feature, defect, research question, design decision, or delivery task.

02 · UNDERSTAND

Gather evidence

Research facts, challenge assumptions, and sharpen domain terms.

03 · DESIGN

Choose a seam

Explore an interface or prototype an uncertain behavior or journey.

04 · BUILD

Implement

Use a test-first loop when requested or when integration tests are needed.

05 · VERIFY

Review changes

Check the result against both repository standards and the originating spec.

06 · DELIVER

Explain the result

Prepare a PR description or guide a human through external steps.

Choose a route

New feature or change

Turn an idea into a buildable change, then check the result.

  1. grilling when the plan or decision needs stress testing.
  2. research for external facts; domain-modeling for project language.
  3. codebase-design for the module interface; prototype for a question best answered by trying it.
  4. tdd when test-first work or integration tests are requested.
  5. code-review, then pr for a PR body.

Bug or regression

Begin with a reproducible symptom and follow the evidence.

  1. diagnosing-bugs owns the diagnosis loop for broken, failing, or slow behavior.
  2. Use codebase-design if the fix raises an interface question.
  3. Use tdd when the requested fix calls for a test-first or integration-test workflow.
  4. code-review checks the change; pr describes it.

Unclear design or decision

Reduce uncertainty before committing to a larger implementation.

  1. grilling tests the assumptions in a plan.
  2. research checks claims against primary sources.
  3. domain-modeling resolves terms and records durable decisions.
  4. prototype tests a state model or user journey.
  5. codebase-design defines a clean module boundary.

How to read this map

Skills are selected by need

  • A bug starts with diagnosis; an open question may start with research or a prototype.
  • Domain modeling and codebase design can support several routes.
  • A simple task may pass through only one or two skills.
