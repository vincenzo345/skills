# Data model design

Load `datamodel-design` through the available skill mechanism, or locate and read its installed SKILL.md when there is no invocation tool. It is the single source for this branch's vocabulary, principles, history guidance, and evolution guidance. It remains independently invocable, like `codebase-design`.

Use the parent design conversation to establish the scope and consequential human decisions. Apply the specialist discipline to the logical representation, constraints, lifecycle, and physical mapping needed by the selected task. Use concrete records and operations to compare alternatives, then return the chosen model, rationale, and unresolved questions to the design record.

Domain modeling owns what a concept means; architecture owns system and storage responsibilities; data model design owns representation and integrity; codebase design owns the interfaces that operate on it. Resolve only the dependency that crosses those responsibilities and retain the other accepted decisions. Prototype a specific uncertain constraint or lifecycle when runnable evidence would help. Migration execution belongs to implementation.
