# Bounded discovery

Use this reference when Workbench knows the desired destination but does not yet know enough to route safely or recommend a consequential decision.

## Start with the smallest useful inquiry

Discovery exists to resolve named uncertainty, not to produce a comprehensive document by default. Record the question, why it matters, who owns the answer, what evidence could settle it, and the decision or stage it unlocks.

Begin with a compact evidence inventory: sources already inspected, relevant surfaces, findings, confidence, and unresolved questions. Reuse that inventory across related activities. Reopen a source only when a new question requires detail not captured there or evidence indicates that the source changed.

Use three depths:

1. **Targeted inspection** — read the named source and the smallest relevant repository, workflow, data, or policy surface. This is the default for intake and bounded changes.
2. **Focused investigation** — create one evidence task, analysis, experiment, or prototype for one material question that inspection cannot answer.
3. **Deep mapping** — expand the uncertainty map breadth-first only when several dependent unknowns exist, evidence conflicts, a choice is hard to reverse or high risk, work crosses sessions or agents, or the user explicitly asks for deep exploration.

Stop escalating when the current question has enough evidence for its agreed decision threshold. Do not map unrelated possibilities, future-proof hypothetical branches, or research facts that cannot change the route, decision, deliverable, or surviving obligation.

## Select a specialist method

- Use repository inspection for current behavior, blast radius, integration boundaries, and existing tests.
- Use research for an external fact that needs authoritative sources.
- Use data analysis for process frequency, delay, defects, demand, or bottlenecks.
- Use a prototype for a behavioral, state-model, feasibility, or visual question that can be answered cheaply without production claims.
- Use domain modeling when terminology or responsibility boundaries are unstable.
- Use grilling only after evidence exposes a consequential decision whose assumptions, tradeoffs, or alternatives need stress-testing.

Give the method one bounded question, its known evidence references, expected output, proof threshold, and authorization boundary. Perform it in the current agent when it shares the same working set; delegate only independent work that justifies the additional context and synthesis. Workbench owns state and accepts or rejects the result; never let a specialist create a competing map or lifecycle.

## Escalation and stopping tests

Escalate one level only when the current level cannot answer a material question and record why. Before adding a map node or another task, ask:

- Which desired outcome, destination requirement, decision, or obligation does this support?
- What becomes possible when it is complete?
- Could a smaller or cheaper evidence action answer it?
- What would falsify the working assumption?
- Who decides when the evidence remains ambiguous?

Discovery is sufficient when every material routing question is either answered, explicitly owned by a human, or honestly recorded as an external/unsupported blocker. “Thorough” is not a completion criterion.
